<objective>
Build the D-53 corpus-baselines reporting surface: a separate JSON payload and generated Markdown
view for the five D-48 baseline records (one candidate measured across five corpora), so those rows
never enter `experiments/LEADERBOARD.md`, whose entire premise is same-corpus comparison.

Purpose: Phase 2 is the first point where five distinct `dataset_sha256` values exist.
`adjudicate` correctly refuses them as candidate arms (D-45, `arena/adjudication.py:205-219`).
Putting them into the leaderboard as `--include` report-only rows would place five
different-corpus rows in a same-corpus table — exactly the misreading D-45 exists to prevent.
Building this surface now, against fixtures, means the operator plan (02-13) only has to run it.

Output: `build_corpus_baselines`, `render_corpus_baselines_markdown`, `write_corpus_baselines`
and their module path constants, plus a two-sided test that the corpus rows and the leaderboard
candidate rows cannot be confused.
</objective>
