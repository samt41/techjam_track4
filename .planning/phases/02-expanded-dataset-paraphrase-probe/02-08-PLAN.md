<objective>
Build the D-43 dataset registry: `data/datasets.json` as canonical committed truth, `docs/datasets.md`
as its generated view, and — the part that turns a recorded checksum into an enforced one — a
name-resolution path that re-hashes the corpus at use time and refuses on drift.

Purpose: MEAS-12 requires the probe to be "frozen before any candidate iterates against it", and
D-04's rule is that retained evidence is a committed file, not a number in prose. A recorded digest
that nothing checks is prose. Pitfall 6 is concrete: `os.replace` on a *file* overwrites silently on
Windows, so a regenerated corpus would leave `data/datasets.json` describing bytes that no longer
exist, with no error anywhere. D-43's filename versioning plus a refuse-if-exists write plus a
resolution-time re-hash closes all three doors.

This plan also owns the corpus-shape invariants that only make sense across a whole corpus:
scenario mix (D-30), pair completeness (MEAS-11), and the three-arm cross-check subset (D-40).

Output: `arena/datasets/registry.py` and its test module, both exercised against temporary corpora —
the committed corpora arrive in plans 02-11 and 02-12, which extend this test module.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/datasets.json` → `run_arena --dataset` | a recorded digest becomes an enforced precondition of every measurement |
| a corpus name → a filesystem path | a name that becomes a filename must be allow-listed and contained |
| an on-disk corpus → a committed digest | the pair whose agreement is the entire meaning of "frozen" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering | Path traversal via a corpus name supplied on the CLI or derived from model output | mitigate | `_DATASET_NAME_RE` allow-list plus `resolve_corpus_path`'s `is_relative_to` containment, mirroring `store.validate_run_id` / `resolve_run_directory`; corpus names are constructed by the driver, never taken from LLM output |
| T-02-07 | Repudiation | A silently regenerated corpus invalidating a committed measurement | mitigate | D-43 filename versioning, `publish_corpus`'s `FileExistsError` refusal, `upsert_entry`'s refuse-on-changed-digest, and `resolve_dataset`'s re-hash at use time (Pitfall 6) |
| T-02-11 | Tampering | Untrusted deserialization of registry or corpus lines | mitigate | `json.loads` only, never pickle/eval/yaml, with domain errors naming path and line |
| T-02-30 | Spoofing | A probe row without a control partner, or a `probe_haiku` row on an unmatched target, silently shrinking the paired n | mitigate | `check_pairing` and `check_cross_check_subset` refuse rather than warn; five and two refusal cases respectively |
| T-02-31 | Information Disclosure | Nothing sensitive is recorded — but a provenance record is where it would leak | mitigate | `DatasetEntry` has no environment, credential or settings field; the whitelist is the field list itself, and the sha256 threat-model sentence (integrity aid, never an authenticity control) is repeated in the dataclass docstring |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install occurs. `pyproject.toml` declares `dependencies = []`; `02-RESEARCH.md` § "Package Legitimacy Audit" records zero packages and zero `[ASSUMED]`/`[SUS]`/`[SLOP]` verdicts |
</threat_model>
