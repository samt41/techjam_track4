    Create `arena/import_legacy_results.py`: a stdlib-only CLI that migrates the
    untracked evaluator `results.json` into the canonical `experiments/baselines/`
    record shape D-04 specifies.

    Public surface:
    - `SESSION_FIELDS: tuple[str, ...]` = `("sample_id", "scenario_type", "hit", "first_hit_turn", "best_rank", "reciprocal_rank")` — exactly the evaluator's per-session record keys.
    - `import_legacy_results(results_path: Path, destination: Path, *, provenance: str) -> tuple[Path, Path]` — reads the JSON object, projects each row in `sessions` down to `SESSION_FIELDS` (dropping any extra key such as `first_miss_reason`), writes `sessions.jsonl` and `summary.json` into `destination`, returns both paths.
    - `main() -> None` — argparse CLI with `--results` (default `results.json`), `--output` (required), `--provenance` (required, free text).

    Serialization must be byte-canonical, matching `experiments/run_public.py:283-294`
    exactly: `json.dumps(payload, indent=2, sort_keys=True) + "\n"` for the `.json`,
    and `"".join(json.dumps(row, sort_keys=True) + "\n" for row in rows)` for the
    `.jsonl`. Fingerprint stability downstream depends on this.

    `summary.json` payload keys, all sorted by `sort_keys=True`:
    `run_id` (from `destination.name`), `provenance` (the `--provenance` string),
    `provenance_complete` (`false`), `code_revision` (`"unknown_revision"`),
    `catalog_sha256` (`"unknown"`), `dataset_sha256` (`"unknown"`),
    `source_sha256` (SHA-256 of the input `results.json`, computed with the 1 MiB
    chunked loop from `run_public.py:275-280`), plus every top-level key of the
    input EXCEPT `sessions`: `sample_count`, `hit_rate_at_10`, `mrr`, `mttc`,
    `efficiency`, `recommended_technical_score`, `scenario_metrics`,
    `reported_token_usage`.

    The three `unknown`/`false` provenance fields are deliberate and must be
    present, not omitted: this record is a rescue of a file that carries no
    provenance, and a summary that silently looked complete would be exactly the
    "fingerprint claims a configuration that was not applied" failure mode D-10
    exists to prevent. Comment the *why* at the field, per repo convention.

    Raise `ValueError` with a lowercase specific message if the input lacks a
    `sessions` key, if `len(sessions) != sample_count`, or if any row is missing a
    field in `SESSION_FIELDS`. Never use `pickle`, `eval`, or a bare `except`
    (threat T-01-07).

    Module constraints: first line `from __future__ import annotations`; full type
    annotations including `-> None`; absolute imports only; stdlib only
    (`argparse`, `hashlib`, `json`, `pathlib`). This module must import NOTHING
    from `evaluator` (D-08 — `tests/test_arena_boundary.py` from plan 01-02 scans
    it) and nothing from `arena` (it is a one-off migration whose whole job is to
    seed the record the rig is later validated against; depending on the rig would
    let a rig bug corrupt its own anchor). State that second reason as the comment.
  </action>
