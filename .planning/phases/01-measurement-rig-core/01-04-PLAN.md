<objective>
Make every candidate declarable, hashable, reproducible and attributable — and
make it impossible for a fingerprint to claim a configuration that was never
applied.

Purpose: MEAS-14 and ROADMAP Success Criterion 5, implemented as D-09's frozen
slotted dataclass whose `fingerprint` is a SHA-256 over canonical JSON, D-10's
construction-time allow-list, and D-11's git-revision capture. In Phases 3 and 4
the arena will compare a handful of candidates and one of them will be promoted to
the shipping submission. If a fingerprint can describe a configuration the `Agent`
silently ignored, the entire bake-off is invalidated in a way no test downstream
would ever catch. D-10 closes that by validating `overrides` against an allow-list
that is exactly what `Agent.__init__` accepts today.

Output: `arena/candidate.py` and its test module. This plan runs in wave 2
alongside plans 01-02 and 01-03, with which it shares no file.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| declared spec → applied `Agent` configuration | The fingerprint is the record of what ran; divergence between the two silently invalidates every comparison built on it |
| repository working tree → recorded provenance | A recorded git SHA that does not describe the code that ran makes a candidate unfalsifiable |
| `arena/` → `experiments/analyze_public.py` | A transitive import path that must not reach `evaluator/` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | `CandidateSpec.overrides` | mitigate | `validate()` rejects any key outside `ALLOWED_OVERRIDES` with a `ValueError` naming it; `agent_kwargs()` is the single construction path so the fingerprint and the applied configuration cannot diverge; `test_fingerprint_changes_with_every_field` proves there are no inert fields |
| T-01-01b | Repudiation | `code_revision()` not recording tree state | mitigate | `code_revision_dirty()` runs `git status --porcelain` and is folded into the fingerprint payload, so a dirty-tree run cannot masquerade as a clean commit |
| T-01-11 | Tampering | git invocation | mitigate | `subprocess.run` with a tuple argv and no `shell=True`; `grep -c 'shell=True'` returns 0 as an acceptance criterion |
| T-01-11b | Tampering | git subprocess failure treated as clean | mitigate | `code_revision_dirty()` returns `True` on `OSError`/`CalledProcessError` — fail closed, proven by `test_dirty_flag_fails_closed` |
| T-01-02c | Tampering | transitive `evaluator` reach via `experiments.analyze_public` | mitigate | Verified in planning that the module imports only `subprocess`, `dataclasses`, `enum`; permanently guarded by plan 01-02's `test_analyze_public_does_not_reach_the_evaluator` |
| T-01-09 | Spoofing | fingerprint treated as tamper-evident | accept | Documented in a code comment: the fingerprint is an integrity and reproducibility aid for a single local user, never an authenticity control |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed; `dependencies = []`, `uv.lock` holds only the virtual root |
