<objective>
Wire the rig together: `arena/arena.py` runs one `CandidateSpec` through the
unmodified organizer evaluator and publishes a provenance-carrying record under
`experiments/baselines/`, and `arena/run_arena.py` exposes both that path and the
adjudication path as one CLI.

Purpose: D-06 keeps `experiments/run_public.py` byte-untouched — it is the
reproducer that produced the retained determinism evidence, and perturbing it costs
a re-verification run and buys nothing. Keeping both means two independent code
paths must agree on `0.92 / 0.524466 / 3.425 / 0.76884`, which is stronger
validation evidence than one path and is itself reportable under Technical
Execution.

Output: the runner, the CLI, and a test module that proves the session-mapping and
spec-fidelity properties using fakes, so the suite keeps its no-catalog-download
property. The expensive evaluation runs themselves are plan 01-09.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| evaluator ground truth → `Agent` | The evaluator holds the hidden target; any leak into the `Agent` invalidates every score this project reports and would be a disqualifying integrity failure |
| declared spec → constructed `Agent` | If the `Agent` receives anything other than the validated overrides, the fingerprint records a configuration that did not run |
| in-progress run directory → published record | An interrupted or partially written record could be mistaken for a completed run |

| T-01-03 | Information disclosure | `_SampleMappingAgent` | mitigate | The wrapper records only `reset` ordering; the UUID to `sample_id` join is performed after `evaluate()` returns; `test_ground_truth_never_reaches_the_agent` asserts over the fake agent's recorded call log |
| T-01-01 | Tampering | `Agent` construction diverging from the spec | mitigate | The `Agent` is constructed from `spec.agent_kwargs()` only, after `spec.validate()`; `test_agent_receives_exactly_the_spec_overrides` fails on any hard-coded override |
