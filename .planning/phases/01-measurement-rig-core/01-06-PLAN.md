<objective>
Turn statistics into a decision. `arena/adjudication.py` runs D-20's five steps in
order, applies D-23's three-part win rule, and names the failing criterion whenever
a candidate falls short.

Purpose: this is the most consequential ordering call in the phase. The
practical-significance floor asks "is this gain big enough to believe and ship?"
and that question must be asked of the BELIEVABLE gain. Applying the floor to the
raw delta would let a candidate clear 0.01 on selection bias alone — precisely the
0.022-0.030 inflation PROJECT.md warns about, which is more than the entire
remaining recall headroom this project has left.

Output: the policy module and its test suite, including the D-01 Layer 3
adjudication controls run on synthetic arms with analytically known answers.
</objective>

    executing D-20 in exactly this order, with a numbered comment block naming each
    step so the ordering is auditable in the source:

    1. For each candidate, `paired_bootstrap` seeded with
       `pair_seed(baseline.spec.fingerprint, candidate.spec.fingerprint, "bootstrap")`
       giving `delta`, the percentile CI and the SE. Compute the joint reporting
       deltas from `metric_summary` on each arm: `hit_rate_delta`, `mrr_delta`,
       `mttc_delta` (candidate minus baseline in each case). D-16 makes
       TechnicalScore the ONLY hypothesis tested; HR@10, MRR and MTTC are always
       reported jointly but never separately tested, because testing three metrics
       would triple the family size for no gain and invite cherry-picking whichever
       term happened to move.
    2. For each candidate, `paired_permutation` seeded with the same pair and the
       label `"permutation"`.
    3. `holm_bonferroni` across the tuple of candidate permutation p-values, in
       candidate order. The family is exactly these candidates against the common
       baseline (D-19). Do NOT include per-scenario results in the family.
    4. Winner's-curse correction. Set `candidate_count = len(candidates)` and
       `correction_k = candidate_count` — that is the number of NON-BASELINE
       candidates whose delta was compared when choosing the champion, since the
       baseline's delta against itself is not a selection option. Compute
       `expected_max_of_k(correction_k)` once and apply
       `corrected_delta = delta - winners_curse_correction(standard_error, correction_k)`
       to EVERY row using that same k, then flag the champion as the row with the
       maximum `delta`, tie-broken by ascending `candidate_fingerprint`. Comment
       both choices: applying the correction uniformly at the family's k is never
       anti-conservative, so no row can clear the floor on selection bias, while a
       correction applied only to the champion would leave every other row
       reporting an uncorrected gain that a later reader could promote by mistake.
       With a single candidate `expected_max_of_k(1)` is `0.0`, so no selection
       happened and no correction is applied — which is correct.
    5. `clears_practical_floor = corrected_delta >= PRACTICAL_FLOOR`. Test the
       CORRECTED delta, never the raw one. Comment that this is D-20 step 5 and
       that applying the floor to the raw delta is the specific anti-pattern this
       ordering exists to prevent.

    Then the D-23 win rule. `exchange_rate_ok` is `True` when
    `hit_rate_delta >= 0.0`, and otherwise `True` only when
    `mrr_delta > EXCHANGE_RATE_PER_MTTC * mttc_delta`. An HR@10 regression is
    disqualifying unless that exchange-rate math clears. Build
    `failed_criteria` as a tuple of the failing criterion names, drawn from exactly
    `"holm_significance"`, `"practical_floor"`, `"hr10_exchange_rate"`, in that
    fixed order. `verdict` is `Verdict.WIN` only when `failed_criteria` is empty.

    Zero-variance guard, applied BEFORE the verdict is computed: when
    `standard_error <= ZERO_VARIANCE_TOLERANCE`, short-circuit to
    `permutation_p = 1.0`, `holm_p = 1.0`, `minimum_detectable_difference = 0.0`,
    `corrected_delta = delta`, `clears_practical_floor = False`, and
    `verdict = Verdict.NO_DIFFERENCE`. Comment why: with delta, SE, CI and MDD all
    collapsing to zero simultaneously, a naive `abs(delta) >= mdd` check evaluates
    `0 >= 0` as True and the rig would declare a detectable difference between a
    candidate and itself. This is a plausible real outcome for a near-null ablation,
    not a hypothetical.

    Non-degenerate verdict selection: when `holm_p < SIGNIFICANCE_ALPHA` the
    candidate is significant and the verdict is decided by the remaining two
    criteria. When `holm_p >= SIGNIFICANCE_ALPHA`, the verdict is
    `Verdict.NOT_DETECTABLE` if `abs(delta) < minimum_detectable_difference` and
    `Verdict.NO_DIFFERENCE` otherwise.

    Return rows in input candidate order, so the caller controls presentation and
    the function itself performs no sorting other than the champion tie-break.
    Raise `ValueError` when `candidates` is empty, when any candidate's fingerprint
    equals the baseline's, or when a candidate's session tuple fails
    `_require_paired` against the baseline (let `arena.statistics` raise that).
